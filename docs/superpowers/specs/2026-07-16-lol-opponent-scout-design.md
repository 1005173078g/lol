# 联盟一区对手战绩助手设计

## 目标

构建一个 Windows 桌面程序。在用户通过 WeGame 启动英雄联盟并进入对局英雄选择或载入阶段后，程序自动识别联盟一区本局敌方玩家及其所选英雄，使用本机当前 WeGame 登录会话查询公开战绩，并在独立窗口中展示分析结果。程序生成适合粘贴到游戏聊天的精简播报，但不自动发送消息。

## 范围

首版只支持合区后的“联盟一区”，只分析敌方五名玩家，统计样本固定为最近 20 场排位。每名玩家展示：

- 游戏 ID 与本局所选英雄；
- 最近 20 场排位胜率；
- 最近 20 场排位 MVP 率；
- 最近 20 场排位最常用位置及占比；
- 最近 20 场中使用本局英雄的场次、胜率和平均 KDA。

不在首版实现其他大区、自动聊天、开机自启动、游戏进程注入、操作 WeGame 图形界面或来源不明的第三方战绩接口。

## 安全与隐私边界

程序只读英雄联盟客户端状态和 WeGame 本地已登录会话，不修改或注入游戏进程，不读取键盘输入，不模拟游戏操作。Cookie、令牌、账号密码及原始会话数据不得写入磁盘、日志或仓库。原始查询数据仅保存在内存，并在对局结束或程序退出后清除。

由于 WeGame 以管理员权限启动 LeagueClientUx，程序也要求以管理员身份运行。程序从 LeagueClientUx 自声明的命令行参数中读取本地 LCU 端口和临时令牌，并对 Riot `rclient` 证书执行固定指纹、主题、颁发者和有效期验证；不得使用“接受所有证书”的回调。令牌只存在于内存中。进入载入或游戏阶段后，阵容优先来自 Riot 官方 Live Client Data API `playerlist`；若英雄选择阶段隐藏敌方身份，则不得绕过该限制。

日志只允许记录时间、运行阶段、脱敏错误类型、HTTP 状态码和缺失字段名称。日志不得包含完整玩家查询响应、会话头、Cookie、令牌或其他凭据。

## 架构

### 对局检测器

以管理员权限监测英雄联盟客户端的只读本地状态，通过 LCU 识别英雄选择、载入和对局结束。为每场对局生成稳定的本地标识，同一局只自动触发一次分析。用户可手动重新查询，但手动操作不得创建重复窗口。

### 阵容读取器

读取双方玩家 ID、阵营和已选择英雄。英雄选择阶段仅使用 LCU 明确提供的数据；载入或游戏阶段使用 Riot 官方 Live Client Data API。只有能够可靠区分敌我并确认敌方阵容时才开始自动查询。若英雄选择阶段隐藏敌方信息，则等待载入阶段；仍无法读取时显示失败原因并提供重试。

### WeGame 战绩适配器

使用本机当前 LeagueClientUx 的 LCU 登录会话查询联盟一区玩家的最近 20 场排位。五名玩家并发查询，每项请求使用短超时和有限重试。适配器输出统一领域模型，使上层界面不依赖 LCU 原始响应结构。

如果 WeGame 接口无法安全确认、会话未登录或响应结构发生变化，适配器必须返回明确错误，不得自动改用不可信数据源。腾讯客户端更新后允许通过后续版本适配接口。

### 分析器

分析器只根据最近 20 场排位计算指标：

- 胜率 = 胜场数 / 有效排位场次；
- MVP 率 = 带有 WeGame MVP 标记的场次 / 有效排位场次；
- 常用位置 = 实际位置出现次数最多的位置，同时展示占比；
- 本局英雄近期战绩 = 20 场样本中该英雄的场次、胜率与平均 KDA。

若 WeGame 没有提供 MVP 标记，MVP 率显示“不可用”，不得用 KDA 推断。若有效排位不足 20 场，使用实际场次并标明样本数量。位置或英雄数据缺失时只隐藏对应指标，不影响其他指标。

### 窗口与播报生成器

程序使用 Windows 原生桌面窗口并常驻系统托盘。状态包括：等待客户端、英雄选择中、等待敌方信息、正在查询、查询完成和查询失败。

敌方五人以独立卡片逐个更新，无需等待全部请求完成。窗口提供“复制精简播报”“重新查询”“保持窗口置顶”和“查看查询状态”。检测到敌方阵容后自动弹出窗口，默认不开机启动。

播报生成器使用已成功查询的数据创建紧凑中文文本。文本优先保留本局英雄表现、异常连胜/低胜率和主要位置，并控制长度以便粘贴到游戏聊天。程序只写入 Windows 剪贴板，不自动聚焦游戏、不模拟按键、不发送聊天。

## 数据流

1. 程序启动并等待英雄联盟客户端。
2. 对局检测器识别新对局。
3. 阵容读取器等待并读取敌方五人及英雄。
4. WeGame 战绩适配器并发查询五名玩家的 20 场排位。
5. 分析器逐个计算指标并推送到窗口。
6. 播报生成器根据已完成结果生成可复制文本。
7. 对局结束后清理内存中的原始数据并回到等待状态。

## 错误处理

WeGame 未登录、客户端未启动、对手隐藏战绩、接口超时、数据不足和响应字段变化均使用独立错误类型。单个玩家查询失败不得阻塞其他玩家。网络请求使用有限重试，避免载入阶段结束后仍无限等待。

程序发生未处理异常时应保留可读的脱敏诊断信息并安全恢复到等待状态；不得因错误输出任何凭据。接口结构无法识别时停止该次查询并提示版本需要适配。

## 发布方式

首版面向 Windows，发布为无需用户另外安装 Python 的可运行 `.exe`。仓库包含中文 README、开发构建步骤、运行说明和发布包生成方法。发布产物不得包含本机路径、会话缓存或任何凭据。

## 测试策略

- 单元测试覆盖胜率、MVP 率、常用位置、本局英雄统计和播报裁剪。
- 使用去标识化的固定响应样本测试 WeGame 响应解析，不提交真实会话数据。
- 集成测试覆盖客户端阶段变化、新对局去重、并发查询、超时、有限重试和单玩家失败。
- UI 测试覆盖逐卡片更新、复制到剪贴板、置顶切换和手动重试。
- 安全测试扫描日志和发布包，确认不含 Cookie、令牌、账号密码或本机真实查询响应。

## 验收标准

- 联盟一区进入对局载入阶段后自动识别敌方五人及所选英雄。
- 正常网络条件下结果逐个出现，目标是大部分数据约 10 秒内完成。
- 每名玩家按可用数据展示最近 20 场胜率、MVP 率、常用位置及本局英雄近期战绩。
- 同一局不会重复弹窗或反复自动请求，手动重试可用。
- 精简播报可一键复制并手动粘贴到游戏聊天。
- WeGame 未登录、数据隐藏、接口失败或程序重启时不崩溃。
- 凭据不写入磁盘、日志、发布包或 GitHub。

## 已知风险

WeGame 国服数据接口不是稳定公开 API，腾讯更新客户端、会话机制或响应结构后可能需要适配。敌方信息在英雄选择阶段可能不可见，程序应等待载入阶段而不是绕过客户端限制。10 秒目标取决于 WeGame 接口响应和国内网络状况，不作为硬性实时保证。
