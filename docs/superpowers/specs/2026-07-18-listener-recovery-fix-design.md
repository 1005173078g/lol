# 监听恢复与启动窗口修复设计

## 问题

监听轮询首次遇到瞬时异常时，异步迭代器的清理路径会再次抛出同一个异常，导致 `watcherActive` 未被复位。界面层虽然持续重试，但每次都会收到“只能存在一个监听器”，因此永久显示“监听失败”。此外，应用启动后只创建窗口却不显示窗口，造成程序像是没有启动。

## 方案

采用最小范围修复：

1. 将监听器状态和活动通道的释放放入无条件执行的清理路径；轮询任务的原始异常仍只向调用方传播一次。
2. 保留现有界面层一秒重试机制，使瞬时异常后的下一次监听可以正常建立。
3. 在应用完成窗口与托盘初始化后立即显示主窗口；关闭按钮仍按现有行为隐藏到托盘。
4. 不改变客户端认证、战绩接口、数据来源或隐私边界。

## 测试

- 回归测试先复现：首次监听因轮询异常结束后，第二次监听可以建立，而不是抛出重复监听异常。
- 启动行为测试验证应用启动流程请求显示主窗口；若现有 WPF 测试边界不适合直接构造 `Application`，则把启动显示决定提取为可测试的最小生命周期组件。
- 运行全部测试、发布脚本和发布产物启动检查。

## 验收标准

- 短暂监听失败后自动重试能够恢复。
- 不会同时运行两个有效监听器。
- 双击 EXE 后主窗口直接出现。
- 现有安全与脱敏测试继续通过。
