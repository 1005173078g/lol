# Live Client 字段兼容与启动窗口修复设计

## 问题

运行中取证确认阶段监听、客户端认证和战绩接口均正常。失败发生在官方 Live Client `playerlist` 解析：国服当前响应新增 `rawSkinName` 和 `skinName`，严格字段白名单拒绝了整份 10 人阵容。此外，应用启动后只创建窗口却不显示窗口，造成程序像是没有启动。

## 方案

采用最小范围修复：

1. 为 `LiveClientPlayerDto` 增加两个已确认的可选皮肤显示字段；保留 `UnmappedMemberHandling.Disallow`，其他未知字段仍会被拒绝。
2. 在应用完成窗口与托盘初始化后立即显示主窗口；关闭按钮仍按现有行为隐藏到托盘。
3. 不改变客户端认证、战绩接口、数据来源或隐私边界。

## 测试

- 回归测试先复现：包含 `rawSkinName` 和 `skinName` 的当前响应解析失败；修复后可正常获得五名敌方玩家。
- 现有测试继续验证任意其他未知字段会触发协议变化错误。
- 启动行为测试验证应用启动流程请求显示主窗口；若现有 WPF 测试边界不适合直接构造 `Application`，则把启动显示决定提取为可测试的最小生命周期组件。
- 运行全部测试、发布脚本和发布产物启动检查。

## 验收标准

- 当前国服 Live Client 皮肤字段不会导致阵容监听失败。
- 未知响应字段仍不会被静默接受。
- 双击 EXE 后主窗口直接出现。
- 现有安全与脱敏测试继续通过。
